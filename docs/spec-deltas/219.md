## §9.13 — ADDED

**Reason:** #219 adds gate-enforced dark/light theme support for fab-app — the user directive is
that the app must follow the OS-level appearance setting, and that this land now, while the app
still has only six bare-minimum screens, so every later E4/E5/E6 screen inherits themed tokens and
gate enforcement from birth (same rationale #217's i18n layer and #218's a11y bar were built on —
this completes the trio of user-directive gate checks). Like both of those, the requirement is
stated generically over whatever semantic roles/screens/themes currently exist, not a hardcoded
per-screen list: a data-driven token registry (`fab-app/src/theme/`) consumed exclusively through
a `useTheme()` hook, a lint rule scoped to all shipped `.tsx` source, and a pure WCAG contrast-ratio
check over registered token pairs — mirroring §9.11's LOCALE_BUNDLES / §9.12's screen-registration-
table "generic over the registered set" pattern one level up. v1 is system-only: no in-app theme
toggle (out of scope per user directive — see PR body for the toggle-triviality note).

**New text (insert after §9.12, before §10):**

> - **9.13** THE SYSTEM SHALL support a dark theme and a light theme, following the device's
>   OS-level appearance setting — no in-app override or manual toggle in this version. Both
>   themes SHALL be expressed as a registered, data-driven set of semantic color tokens (a
>   `THEMES` registry keyed by theme name, mirroring §9.11's locale-bundle registry and §9.12's
>   screen-registration table one level up) covering, at minimum: a primary background surface, a
>   secondary/elevated surface, primary text, de-emphasized/secondary text, a decorative border
>   tone, an accent/call-to-action tone, and danger/warning/success status tones. Every shipped UI
>   component SHALL consume color exclusively through these tokens (a `useTheme()` hook resolving
>   the active theme from the OS appearance setting), never a hardcoded color literal. WHEN the
>   OS-level appearance setting changes THE SYSTEM SHALL re-render the active screen under the
>   newly selected theme without requiring an app restart. THE SYSTEM SHALL enforce, as part of
>   the merge gate (network-disabled, per §13 invariant 10): (a) zero hardcoded color literals in
>   shipped screen source (test fixtures excluded, the same scoping §9.11's no-hardcoded-string
>   and §9.12's a11y lint rules use); and (b) WCAG AA contrast (4.5:1 for normal text) for every
>   foreground-role-on-background-role pair actually rendered by shipped screens, checked via a
>   pure, independently-unit-tested contrast-ratio function, in every registered theme. Both checks
>   SHALL be generic over whatever theme set, token pairs, and screens currently exist — adding a
>   theme, a token pair, or a screen requires no change to the check logic itself, the same
>   guarantee §9.11 makes for locales and §9.12 makes for screens.

**Cross-references:** §13 invariant 10 (all merge-gating tests pass with the network disabled —
the color-literal lint rule and the token-contrast check both run inside `fab-app`'s `npm run
gate` with no network access, same as §9.11's and §9.12's checks); §9.11 (the "generic over a
registered set, not a hardcoded list" pattern this section reuses for themes instead of locales —
its own no-hardcoded-literals lint override is the direct scoping precedent for this section's
color-literal lint rule); §9.12 (the screen-registration-table pattern this section's per-screen
theme-render check reuses, and whose own accessibility walk is extended by this delta to run under
both themes as well as every registered locale).

**Design-doc note:** `docs/design/app-E3.md`'s "Interfaces / contracts" section has a binding
gate-contract line that currently reads "typecheck + lint (incl. no-hardcoded-JSX-literals rule +
a11y lint) + tests + en/pt-BR key-parity check + per-screen a11y assertions. All gate tests pass
with the network disabled (§13 invariant 10)." — this line goes stale the moment this delta lands,
since it doesn't mention theming. It needs `+ color-literal lint + token-contrast check (both
themes)` appended (still "all offline" — both new checks run inside the same network-disabled
`npm run gate`), for the orchestrator to fold in at merge alongside §9.13 above.
