## §7.11 — REVISED

**Reason:** #134 (APP-022) builds the eval harness (§8.3-§8.5) and, per §13 invariant 8 ("no
model ... is released without passing the eval gate"), a released model's per-suite eval scores
must be recorded in its manifest — the same "no lane invents its own manifest shape" contract
§7.11 already established for every other release-relevant field (artifact hashes, license ids,
compatibility versions). §7.11's original wording enumerated the shared package's coverage
(model pack, knowledge pack, delta pack, corpus snapshot, license identifiers, revoked-versions
list) without naming eval scores, even though docs/design/app-E2.md already anticipated this
exact extension ("Scores land in the release-manifest shape owned by @fab/manifest-schema —
extend that package if fields are missing, never invent a parallel shape"). This delta makes
that anticipated extension the recorded contract: `@fab/manifest-schema`'s `ModelPackManifest`
now REQUIRES an `evalScores` field (`manifest-schema/src/evalScores.ts`) carrying, per eval run,
every one of the eight §8.4 suites' `{suiteId, counts {correct, incorrect, abstained}, score}` —
enforced with runtime (not just TS-type) guards: all eight canonical suite ids must be present,
no duplicate suiteId, and no suite may report zero graded items (a vacuous "pass"). The
per-embedder-version calibration outputs §9.7/§10.9 already require (`retrievalFloor`/
`oodThreshold`) needed no schema change — `KnowledgePackManifestSchema` already carries both
fields with the `oodThreshold < retrievalFloor` invariant enforced (§10.9), and
`pipeline/src/eval/calibration.ts` is built to feed exactly that existing shape.

**Original wording:**

> **7.11** THE SYSTEM SHALL define the manifest and compatibility schema (model pack,
> knowledge pack, delta pack, corpus snapshot; including per-artifact license identifiers and
> the revoked-versions list) as a versioned shared package consumed by both `pipeline/`
> (producer) and `fab-app` (consumer), with schema-validation helpers and fixtures — no lane
> invents its own manifest shape.

**Replacement wording:**

> **7.11** THE SYSTEM SHALL define the manifest and compatibility schema (model pack,
> knowledge pack, delta pack, corpus snapshot; including per-artifact license identifiers, the
> revoked-versions list, and — on the model pack manifest — the per-suite eval-gate scores
> §8.5/§13 invariant 8 requires before release) as a versioned shared package consumed by both
> `pipeline/` (producer) and `fab-app` (consumer), with schema-validation helpers and fixtures —
> no lane invents its own manifest shape. The eval-scores field SHALL enforce, at the schema
> level (not merely via TypeScript types), that every one of §8.4's named suites is present with
> no duplicates and no suite reporting zero graded items.

**Cross-references:** §8.3-§8.5 (the eval harness this manifest field records the output of);
§8.4 (the eight named suites — `EVAL_SUITE_IDS` in `manifest-schema/src/evalScores.ts` is now
the single canonical list, re-exported by `pipeline/src/eval/types.ts` rather than redeclared);
§9.7/§10.9 (calibration — unaffected; `KnowledgePackManifestSchema`'s existing
`retrievalFloor`/`oodThreshold` fields and invariant already covered this, confirmed rather than
changed); §13 invariant 7 (reproducibility — a released model's manifest alone now carries
enough to audit whether it actually passed the eval gate, not just that training/export
happened); §13 invariant 8 (this is the field that closes the loop between "no model ships
without passing the eval gate" and an actual, schema-enforced, non-fabricable record of having
done so).

**Design-doc note:** `docs/design/app-E2.md`'s Interfaces/contracts section already states
"Scores land in the release-manifest shape owned by `@fab/manifest-schema` — extend that package
if fields are missing, never invent a parallel shape" and its Data models section already
sketches `SuiteResult`/`EvalRunSummary`. No change to the design doc is needed — this delta
documents that its anticipated extension has now landed with a concrete, runtime-guarded shape.
